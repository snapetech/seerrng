## Confirmed audit defects

1. Blocklist was hidden for already-available titles. Corrected so permission controls visibility and blocklisted state disables the stable action.
2. Books discovery could retain an unusable empty Open Library provider response and repeatedly render `No results`. Corrected by rejecting empty cached provider payloads and retrying uncached.
3. Detail actions used combined permission-and-state conditions, causing Manage and Report an Issue to disappear and shift the row. Corrected across Movie, Series, Music, and Book; the final production build verifies the shared layout and a live disabled Book state.
4. Series live keyword filtering sent the supported `search` parameter, but the OpenAPI contract rejected it as unknown before the route ran. Added the missing bounded search parameter to `/discover/tv` and a contract-validator check; the final production build verifies live multi-word filtering and top-bar activity.
5. Multi-word page-level searches were routed with `+` separators, while API request validation accepted the same values only with percent-encoded spaces. Music reproduced this as `No results` for `london grammar` despite 20 relevant API results with `%20`; the shared route builder and regression test now require `%20` for every page using it.
6. Book keyword searches used Open Library's broad composite `q` field and then treated hidden subject tags as visible keyword evidence. This reproduced the reported `windows 11` novel results. Provider queries and local relevance checks now require every term in the visible title or author fields; regression coverage excludes subject-only and publisher-only matches.
7. Global Book search used the same broad provider response without the Discover Books local relevance gate, so Book filtering still included hidden-metadata-only titles. It now uses the same field-limited title/author provider query and local all-term validation, with route-level regression coverage.
8. Plex-linked profile pictures always fell back to the generic avatar because the remote proxy intentionally has no provider base URL, while the URL resolver incorrectly required a base even for an already absolute HTTPS URL. The resolver now accepts validated absolute remote-avatar URLs; regression tests cover that path, and POSIX-only cache security tests stay active in Linux CI while being explicitly skipped on Windows systems that cannot create the required links or expose POSIX modes.
9. A Book detail could correctly show an active Audiobook request while the same request modal allowed a manual switch back to Audiobook, labeled it Ready to Request, and left its submit action enabled. The modal now applies the backend's overlapping-format rule before submission, displays Requested, disables the action for active overlaps, and still allows the complementary Book or Audiobook format.
10. The repository's formatting commands depended on Unix `find`/`xargs` pipelines, so the same pull-request formatting gate could not be run reliably from the Windows laptop. Both write and check modes now use one Node runner that obtains tracked and untracked, non-ignored files directly from Git and invokes the pinned Prettier CLI in bounded batches; GitHub retains the identical `pnpm format:check` entry point.
11. The documentation build treated exact quoted design placeholders such as `<status>` as MDX components and failed compilation. The quoted instructions remain complete and unchanged in meaning, while the placeholders are now code-delimited so the documentation site renders them literally.
12. The pinned GitHub Linux image measured roughly 55 minutes for the expanded 1,902-test suite, beyond the former 45-minute job limit, and its graceful-shutdown fixtures needed 5.7–7.3 seconds to initialize under load. The Unit Tests ceiling is now 75 minutes and the fixture readiness bound is 20 seconds; the shutdown behavior itself remains fully asserted rather than skipped on Linux.
13. The setup screen reused one translation identifier for both “Sign In” and “Sign in to your account.” Message extraction therefore selected a different default on Windows and Linux according to filesystem traversal order, allowing the Windows check to pass while the pinned Linux build rejected the catalog. The two meanings now have distinct identifiers, the English catalog preserves both labels, and extraction is deterministic across both platforms.
14. The Cypress preparation and start package scripts embedded POSIX environment-assignment syntax, so the laptop could not execute the same end-to-end commands used by GitHub. Preparation now relies on the test database script's own safe default, and the start command uses a platform-neutral Node launcher that preserves explicit environment overrides while supplying the same isolated config, production mode, and migration-skip defaults on Windows and Linux.
15. The browser suite still encoded several pre-refresh routes, labels, hidden-action assumptions, and control layouts. It now exercises the refreshed Discover filters, stable disabled Manage action, Series season/episode browser, separate standard and permission-gated 4K detail actions, request modal actions, issue dropdown, current user-request route, and cross-format Music/Book flows. The complete production browser run passed all 19 spec groups: 78 active checks passed and 32 live-credential checks remained intentionally pending, with zero failures.
16. Book issue details collapsed Ebook and Audiobook service actions into one generic Bookshelf link, which could hide a valid second configured instance. Format-specific Open Ebook and Open Audiobook actions are restored whenever their corresponding service links exist, and the contract/browser coverage now requires both to remain independently available.
17. The cross-platform formatting runner supplied every Git-selected path directly to Prettier, which makes explicit files bypass `.prettierignore`; the laptop cache concealed four vendored generated files that a clean Linux checkout rejected. The runner now asks Prettier's own file-info API to apply both `.prettierignore` and `.gitignore` before batching, so cached and fresh Windows/Linux runs inspect the same intended file set.
18. The Cypress server already had a narrowly scoped `E2E_TESTS` bypass for production API and authentication rate limits, but its production-mode launcher never enabled that flag. Longer browser runs could therefore exhaust the 600-request window and lock out later test logins with HTTP 429 responses. The isolated Cypress launcher now enables the existing test-only bypass; ordinary preview and deployed production servers retain all rate limits.
19. The first pull-request formatting runs exposed two environment-sensitive assumptions: GitHub's minimal lint container does not include the Git executable, and its checkout fallback uses a source archive from which this repository intentionally excludes every `*ignore`, Markdown, and `docs` file. Layered ignore files plus a local Prettier cache could also conceal intentionally excluded generated files. The cross-platform formatting runner now lets Prettier traverse the repository directly, uses one packaged root-level `prettier-scope.txt` for application and nested-workspace generated output, and does not cache validation results. Keeping the scope file at the repository root makes its patterns resolve identically on every platform. The Alpine validation job now installs Git before checkout so the acceptance ledger and style standard required by the production build are present. Together these changes avoid Windows command-line limits, remove hidden discovery behavior, preserve lean release archives, and give clean Windows/Linux/GitHub runs the same deterministic file scope. The current-batch contract rejects restoring Git discovery or formatting cache, requires the critical generated-output exclusions, and guards the complete-checkout prerequisite.
20. Pull-request code scanning traced HTTP-controlled values through the new local-avatar pipeline and also identified request interpolation in TVDB log messages. Avatar uploads now create a validated Buffer copy at the route boundary, storage filenames use a fixed-width hashed user key plus a canonical content-hash basename, cleanup uses fixed comparisons rather than a dynamic regular expression, and authorized reads use the persisted user identity. TVDB failures now use constant messages with structured numeric metadata. Focused regression tests and the expanded current-batch contract guard these boundaries; the deliberate synthetic test of the explicitly opted-in trusted-LAN HTTP fallback is narrowly documented for code scanning.
21. The first exact merged-commit container build exposed that `.dockerignore` intentionally removed all documentation while the production `prebuild` now requires the acceptance ledger and UI standard. The build context still excludes the documentation tree by default but explicitly retains those two contract files. The container-security tooling test reads `.dockerignore` outside the build context and fails if either narrow exception is removed, while the container's prebuild proves the retained files satisfy the same 80-file contract as checkout builds.
